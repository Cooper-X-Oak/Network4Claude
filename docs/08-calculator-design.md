# 成本计算器设计文档

## 一、计算器概述

### 1.1 目标

帮助用户根据实际用量，找出最经济的 Claude 使用方案。

### 1.2 核心功能

- 输入：用户的 input/output/cache token 用量
- 输出：各方案的实际成本对比
- 推荐：最适合的方案和使用建议

---

## 二、方案对比

### 2.1 官方 API 直接付费

**成本计算**：
```
成本 = (Input × Pi + Output × Po + Cache × Pc) × 汇率 + 网络成本
```

**优势**：
- 按量付费，用多少付多少
- 缓存便宜（0.1x 输入价格）
- 无封号风险

**劣势**：
- 需要梯子（网络成本）
- 需要信用卡
- 轻度用户不划算

---

### 2.2 官方订阅 Pro ($20/月)

**成本计算**：
```
成本 = $20 × 汇率 + 网络成本 = ¥140 + ¥29 = ¥169
```

**容量估算**：
```
API 等价价值 = $20 × 42.475 = $849.50
容量 = $849.50 / 单位成本
```

**优势**：
- 固定成本，可预测
- 中度用户性价比高
- 稳定可靠

**劣势**：
- 有用量限制
- 需要梯子
- 重度用户不够用

---

### 2.3 官方订阅 Max ($200/月)

**成本计算**：
```
成本 = $200 × 汇率 + 网络成本 = ¥1400 + ¥29 = ¥1429
```

**容量估算**：
```
API 等价价值 = $200 × 42.475 = $8,495
容量 = $8,495 / 单位成本
```

**优势**：
- 大用量支持
- 高优先级
- 更少限流

**劣势**：
- 价格高
- 需要梯子
- 轻中度用户浪费

---

### 2.4 普通中转站

**成本计算**：
```
成本 = (Input × Pi × 1.2 + Output × Po × 1.2 + Cache × Pc × 5) × 汇率 + 风险成本
```

**定价特点**：
- 输入/输出：加价 20%
- 缓存：加价 400%（5 倍）

**优势**：
- 无需梯子
- 无需信用卡
- 即开即用

**劣势**：
- 缓存贵（重度用户不划算）
- 可能跑路
- 数据隐私风险

---

### 2.5 廉价中转站

**成本计算**：
```
成本 = (Input × Pi × 1.5 + Output × Po × 1.5 + Cache × Pc × 10) × 汇率 + 风险成本 × 2
```

**定价特点**：
- 输入/输出：加价 50%
- 缓存：加价 900%（10 倍）

**优势**：
- 轻度用户可能更便宜
- 无需梯子

**劣势**：
- 缓存极贵
- 高风险（跑路、限流）
- 服务质量差

---

### 2.6 自建中转站（团队）

**成本计算**：
```
成本 = API 成本 + 基础设施成本（VPS + 开发维护）
基础设施成本 ≈ ¥500/月（可分摊）
```

**适用场景**：
- 团队 10-20 人
- 月用量 > 10x Pro
- 有技术能力

**优势**：
- 完全可控
- 数据安全
- 成本可分摊

**劣势**：
- 需要技术能力
- 初期投入高
- 维护成本

## 三、三种计量方式

### 3.1 用户承担成本

**定义**：用户实际支付的人民币

**计算**：
```
用户成本 = API 成本 + 网络成本 + 风险成本 + 其他隐性成本
```

**示例**：
- 官方 API：¥8,495（API）+ ¥29（网络）= ¥8,524
- 中转站：¥12,000（API）+ ¥0（网络）+ ¥100（风险）= ¥12,100

---

### 3.2 站内货币

**定义**：中转站的积分/点数/余额

**特点**：
- 与美元不是 1:1 关系
- 通常有充值优惠
- 可能有有效期

**换算**：
```
站内货币 = 用户充值金额 / 充值汇率
实际成本 = Token 用量 × 站内价格 × 充值汇率
```

**示例**：
- 充值 ¥100 = 15 美元站内余额（汇率 6.67）
- Sonnet Input: $3/1M → 实际成本 = 3 × 6.67 = ¥20/1M

---

### 3.3 模型货币

**定义**：API 的 token 计费（美元）

**特点**：
- 官方定价标准
- 不同模型价格不同
- 缓存有折扣

**定价表**（Sonnet 4.6）：
| 类型 | 价格 (USD/1M) |
|------|--------------|
| Input | $3 |
| Output | $15 |
| Cache Read | $0.3 |
| Cache Write | $3.75 |

## 四、缓存价格差异

### 4.1 官方缓存定价

**Cache Read**：
- Sonnet: $0.3/1M（输入的 10%）
- Opus: $1.5/1M（输入的 10%）
- Haiku: $0.03/1M（输入的 12%）

**优势**：
- 极低的缓存成本
- 鼓励使用缓存
- 重度用户友好

---

### 4.2 中转站缓存定价

**普通中转站**：
- Cache Read ≈ Input × 0.5-1.0（50%-100%）
- 相当于官方的 5-10 倍

**廉价中转站**：
- Cache Read ≈ Input × 1.0-2.0（100%-200%）
- 相当于官方的 10-20 倍

**原因**：
- 中转站也要付官方缓存费
- 加上自己的利润和成本
- 缓存管理复杂度高

---

### 4.3 对不同用户的影响

**轻度用户**（缓存 < 1B/月）：
```
官方：1,000M × $0.3 = $300 ≈ ¥2,100
中转站：1,000M × $1.5 = $1,500 ≈ ¥10,500
差额：¥8,400（但总量小，影响有限）
```

**重度用户**（缓存 > 10B/月）：
```
官方：10,000M × $0.3 = $3,000 ≈ ¥21,000
中转站：10,000M × $1.5 = $15,000 ≈ ¥105,000
差额：¥84,000（巨大差异！）
```

**结论**：
- 轻度用户：缓存价格影响小，中转站可接受
- 重度用户：缓存价格影响大，必须用官方

## 五、隐性成本

### 5.1 网络成本

**官方方案必需**：
- 自建 VPS：¥29/月（搬瓦工）
- 商业梯子：¥17-50/月
- 企业专线：¥200+/月

**中转站不需要**：
- 直接访问，无需梯子
- 但可能有其他限制

---

### 5.2 合规成本

**企业用户**：
- 数据合规审查
- 安全评估
- 合同签署
- 可能需要私有化部署

**成本**：
- 小企业：¥0-1,000/月
- 中大企业：¥5,000-50,000/月

---

### 5.3 身份成本

**官方**：
- 需要国外手机号/邮箱
- 需要信用卡
- 可能需要身份验证

**中转站**：
- 通常只需邮箱
- 支持支付宝/微信
- 门槛低

---

### 5.4 风险成本

**被封号风险**：
- 官方：低（遵守规则即可）
- 中转站：中高（可能被官方封禁）

**服务中断风险**：
- 官方：极低
- 中转站：中高（可能跑路）

**数据泄露风险**：
- 官方：低
- 中转站：中高（不可控）

**量化**：
```
风险成本 = 潜在损失 × 发生概率
示例：被封号导致业务中断，损失 ¥10,000，概率 10%
风险成本 = ¥10,000 × 10% = ¥1,000/月
```

## 六、不同用户群体分析

### 6.1 轻度用户（< 100M input/月）

**特征**：
- 偶尔使用
- 对价格敏感
- 对稳定性要求不高

**推荐方案**：
1. 廉价中转站（如果缓存少）
2. 普通中转站
3. Pro 订阅（如果想要稳定）

**原因**：
- 总成本低，差异不大
- 无需折腾梯子
- 风险可接受

---

### 6.2 中度用户（100-500M input/月）

**特征**：
- 日常使用
- 需要稳定性
- 有一定预算

**推荐方案**：
1. Pro 订阅 + 纯净线路
2. 官方 API（如果用量波动大）

**原因**：
- 固定成本可预测
- 稳定性好
- 性价比高

---

### 6.3 重度用户（> 500M input/月）

**特征**：
- 高频使用
- 大量缓存
- 对稳定性要求高

**推荐方案**：
1. 官方 API + 纯净线路
2. Max 订阅（如果在限额内）

**原因**：
- 缓存便宜，节省大量成本
- 稳定可靠
- 按量付费更灵活

---

### 6.4 团队用户（10-20 人）

**特征**：
- 多人使用
- 用量巨大（可能 > 10x Pro）
- 需要统一管理

**推荐方案**：
1. 自建中转站
2. 多个 Max 订阅
3. 企业 API 账号

**原因**：
- 成本可分摊
- 统一管理方便
- 数据安全可控

**成本对比**：
```
方案 A：20 个 Pro 订阅 = 20 × ¥169 = ¥3,380/月
方案 B：自建中转站 = API 成本 + ¥500 ≈ ¥2,000-3,000/月
方案 C：10 个 Max 订阅 = 10 × ¥1,429 = ¥14,290/月（如果用量极大）
```

## 七、经济边界分析

### 7.1 Pro vs 中转站

**边界条件**：
```
Pro 成本 = 中转站成本
¥169 = (I × 3 × 1.2 + O × 15 × 1.2 + C × 0.3 × 5) × 7

假设 O = I × 0.0475, C = I × 13.36：
¥169 = I × (3.6 + 0.855 + 12.06) × 7
¥169 = I × 115.605
I = 1.46M

结论：输入 > 1.46M/月，Pro 更划算
```

---

### 7.2 Pro vs API

**边界条件**：
```
Pro 成本 = API 成本
¥169 = (I × 3 + O × 15 + C × 0.3) × 7 + ¥29

假设 O = I × 0.0475, C = I × 13.36：
¥140 = I × (3 + 0.7125 + 4.008) × 7
¥140 = I × 54.04
I = 2.59M

结论：输入 < 2.59M/月，Pro 更划算
```

---

### 7.3 Max vs API

**边界条件**：
```
Max 成本 = API 成本
¥1,429 = (I × 3 + O × 15 + C × 0.3) × 7 + ¥29

假设 O = I × 0.0475, C = I × 13.36：
¥1,400 = I × 54.04
I = 25.9M

结论：输入 < 25.9M/月，Max 更划算
```

## 八、计算器实现

### 8.1 输入参数

- 输入 Token (M)
- 输出 Token (M)
- 缓存 Token (M)
- 模型类型（Sonnet/Opus/Haiku）
- 网络成本（¥/月）
- 风险成本（¥/月）

### 8.2 计算逻辑

```javascript
// 1. 计算官方 API 成本
apiCost = (input × Pi + output × Po + cache × Pc) × USD_TO_CNY

// 2. 计算各方案成本
solutions = [
    { name: '官方 API', cost: apiCost + networkCost },
    { name: 'Pro', cost: 140 + networkCost, capacity: proCapacity },
    { name: 'Max', cost: 1400 + networkCost, capacity: maxCapacity },
    { name: '中转站', cost: relayCost + riskCost },
    { name: '廉价中转站', cost: cheapRelayCost + riskCost * 2 },
    { name: '自建', cost: apiCost + 500 }
]

// 3. 排序并找出最优
solutions.sort((a, b) => a.cost - b.cost)
best = solutions[0]

// 4. 生成推荐
if (input < 100) {
    recommend = '中转站或 Pro'
} else if (input < 500) {
    recommend = 'Pro + 纯净线路'
} else {
    recommend = '官方 API 或 Max'
}
```

### 8.3 输出结果

- 各方案成本对比（卡片形式）
- 最优方案标记
- 详细成本构成
- 优缺点分析

## 十、总结

### 10.1 关键发现

1. **缓存是关键**：重度用户必须用官方，缓存便宜 5-10 倍
2. **网络成本可忽略**：相比 API 成本，网络成本（¥29）几乎可忽略
3. **订阅有边界**：Pro 适合中度用户，超过限额必须用 API
4. **团队需自建**：10+ 人团队，自建中转站最划算

### 10.2 决策树

```
用量 < 100M？
  ├─ 是 → 中转站
  └─ 否 → 用量 < 500M？
      ├─ 是 → Pro 订阅
      └─ 否 → 官方 API 或 Max
```

### 10.3 未来优化

- 添加更多中转站定价
- 支持自定义定价
- 添加团队成本分摊计算
- 支持多模型混合使用
- 添加历史数据分析
